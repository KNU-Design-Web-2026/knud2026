# 코드 스타일 컨벤션

## TypeScript

- `strict` 모드를 유지한다.
- `any`를 사용하지 않는다. 불확실한 값은 `unknown`으로 받고 좁혀 사용한다.
- 외부 입력, 환경변수, DB 결과는 신뢰하지 않고 경계에서 검증한다.
- `type`을 기본으로 사용하고 선언 병합이나 명시적 확장이 필요한 경우에만 `interface`를 사용한다.
- 불필요한 타입 단언과 non-null assertion(`!`)을 피한다.
- 공개 함수의 입력과 반환 타입은 호출자가 이해할 수 있게 명확히 표현한다.
- 매직 넘버와 반복되는 문자열은 의미 있는 상수로 추출한다.

## 가져오기와 내보내기(import/export)

- import 순서는 Node·프레임워크, 외부 패키지, `@/` 내부 모듈, 상대 경로, 스타일 순으로 구분한다.
- 타입 전용 import에는 `import type`을 사용한다.
- 설정 후 프로젝트 내부 import에는 `@/` alias를 사용한다.
- 같은 기능 안의 가까운 파일에는 상대 경로를 허용한다.
- 순환 의존성을 만들지 않는다.
- 일반 컴포넌트는 named export를 기본으로 한다. Next.js 예약 파일의 default export는 예외다.

## React와 Next.js

- Server Component를 기본으로 한다.
- 상태, 이벤트, Effect, 브라우저 API가 필요한 가장 작은 경계에만 `'use client'`를 선언한다.
- 페이지는 화면 조합을 담당하고 도메인 로직은 기능 모듈에 둔다.
- 컴포넌트는 하나의 명확한 책임을 갖고 props는 필요한 최소 값만 받는다.
- 파생 가능한 값을 별도 state로 중복 저장하지 않는다.
- Effect에는 구독, 타이머, 이벤트 리스너 정리 로직을 포함한다.
- 성능 최적화 Hook은 측정된 문제나 명확한 재렌더링 경계가 있을 때 사용한다.

## 서버와 데이터

- Route Handler에서 DB 쿼리를 직접 작성하지 않는다.
- 서버 흐름은 `route/action → validation/auth → service → repository` 경계를 따른다.
- 관리자 UI를 숨기는 것만으로 권한을 보호하지 않고 mutation 직전에 서버에서 다시 확인한다.
- 비밀값과 DB 클라이언트는 Client Component에 import하지 않는다.
- 롤링페이퍼 편지는 완전 삭제보다 `deletedAt`을 기록하는 Soft Delete를 기본으로 한다.
- 공개 편지 조회는 숨김 처리된 레코드를 제외한다.
- 시간은 UTC로 저장하고 표시 시점에 필요한 시간대로 변환한다.
- 정적 작품·작가 데이터도 빌드 과정에서 타입과 필수 필드를 검증한다.

## UI와 인터랙션

- 색상, 타이포그래피, 간격, z-index는 디자인 토큰으로 관리한다.
- 반응형은 모바일 최소 너비부터 확인하고 콘텐츠 최대 너비와 여백 규칙을 유지한다.
- 이미지에는 크기 또는 비율을 지정해 레이아웃 이동을 줄인다.
- 큰 이미지와 영상은 목적에 맞는 포맷과 크기로 최적화한다.
- 포인터 기반 인터랙션은 터치와 키보드 환경의 대체 동작을 제공한다.
- 애니메이션은 `prefers-reduced-motion` 설정을 존중한다.

## 접근성

- 의미에 맞는 HTML 요소를 우선 사용한다.
- 모든 상호작용 요소는 키보드로 접근하고 조작할 수 있어야 한다.
- 포커스(focus) 상태를 제거하지 않는다.
- 의미 있는 이미지에는 대체 텍스트를 제공하고 장식 이미지는 비워 둔다.
- 색상만으로 상태를 전달하지 않는다.
- 폼 오류는 입력 요소와 프로그램적으로 연결한다.

## 주석과 오류 처리

- 코드가 무엇을 하는지보다 왜 필요한지를 주석으로 설명한다.
- 오래된 코드와 주석 처리된 코드는 남겨두지 않고 Git 이력에서 확인한다.
- 사용자에게는 이해 가능한 오류 상태를 제공하고 서버 로그에는 민감정보를 기록하지 않는다.
- 예상 가능한 오류와 프로그래밍 오류를 구분하고 오류를 무시하는 빈 `catch`를 사용하지 않는다.
