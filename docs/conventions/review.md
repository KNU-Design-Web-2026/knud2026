# 리뷰 및 완료 기준

모든 항목을 기계적으로 수행하기보다 변경 범위에 해당하는 항목을 검증하고, 생략한 검증은 이유를 남긴다.

## 기능과 범위

- 요청된 요구사항과 완료 조건을 충족한다.
- 관련 없는 리팩터링, 포맷 변경, 의존성 추가가 섞이지 않았다.
- 빈 상태, 오류 상태, 로딩 상태와 긴 콘텐츠를 확인했다.
- 데이터 구조나 사용자 동작이 바뀌면 관련 문서도 갱신했다.

## UI 검증

- 최소 360px 모바일, 768px 전후 태블릿, 1280px 이상 PC에서 확인한다.
- 피그마와 비교해 레이아웃, 타이포그래피, 색상, 이미지 비율을 확인한다.
- 키보드 탐색, focus, 대체 텍스트, 색상 대비를 확인한다.
- 인터랙션에 터치 대체 동작과 reduced motion 처리가 있다.
- UI 변경 PR에는 비교 가능한 스크린샷 또는 영상을 첨부한다.

## 서버와 보안

- 모든 외부 입력이 서버에서 검증된다.
- 관리자 mutation은 서버에서 인증과 권한을 확인한다.
- 익명 편지 작성에는 길이 제한과 반복 요청 방어가 있다.
- 환경변수, 토큰, 개인정보가 코드·로그·클라이언트 번들에 노출되지 않는다.
- 삭제 동작과 실패 시 사용자 상태가 정의되어 있다.

## 자동 검증

프로젝트 생성 시 다음 package script를 표준으로 제공한다.

```text
lint
typecheck
test
build
```

- 변경 범위에 맞는 테스트를 먼저 실행한다.
- 완료를 선언하기 전에 lint와 type-check를 실행한다.
- 배포에 영향을 주는 변경은 build까지 확인한다.
- 실행할 수 없는 검증은 성공한 것처럼 보고하지 않고 이유를 기록한다.

## 변경 내역 검토

- `git diff --check`가 통과한다.
- 임시 로그, 디버그 코드, 사용하지 않는 파일이 없다.
- `.env`와 생성 파일이 추적되지 않는다.
- 새 의존성, 환경변수, 마이그레이션은 문서와 PR에 명시한다.
- 에이전트는 사용자가 요청하지 않은 변경을 스테이징하거나 커밋하지 않는다.
