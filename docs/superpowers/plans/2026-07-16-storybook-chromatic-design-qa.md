# Storybook·Chromatic 및 디자인 QA 문서화 계획

> **에이전트 작업자용:** 이 계획을 작업별로 구현할 때 `superpowers:subagent-driven-development` 또는 `superpowers:executing-plans`를 사용한다. 진행 상태는 체크박스(`- [ ]`)로 추적한다.

**목표:** Storybook과 Chromatic을 도입하는 이유를 기록하고 디자이너 질문과 개발자 답변을 버전 관리되는 디자인 문서로 보존한다.

**구조:** 도구 선정 근거는 ADR-0002에, 제품 논의는 `docs/design/`에 저장하고 루트 에이전트 안내에서 디자인 문서 목차를 연결한다. Markdown은 의사결정 기록, Storybook은 실행 가능한 UI 상태, Chromatic은 시각 회귀와 검수 역할을 담당한다.

**기술 요소:** Markdown, Storybook 문서화 방식, Chromatic 시각 테스트 및 UI 검수

## 전체 제약사항

- 이번 문서 변경에서는 Storybook이나 Chromatic을 설치하거나 설정하지 않는다.
- Next.js 애플리케이션 생성 전에 정확한 패키지 버전을 선택하지 않는다.
- 현재 staging되지 않고 커밋되지 않은 변경을 보존한다.
- 어떤 파일도 staging하거나 커밋하지 않는다.
- 프로젝트 문서는 한국어, 코드 식별자는 영어를 사용한다.

### 작업 1: Storybook과 Chromatic 결정 기록

**파일:**

- 생성: `docs/architecture/adr/0002-use-storybook-and-chromatic.md`

**입출력:**

- 입력: ADR-0001과 합의된 디자인 검수 흐름
- 출력: UI 문서화와 시각 검수 도구의 기준 문서

- [x] **1단계: ADR-0002 작성**

배경, 결정, 역할, 검토한 대안, 한계, 도입 시점, 결과를 기록한다. Markdown은 의사결정, Storybook은 결정적인 컴포넌트 상태와 인터랙션 예시, Chromatic은 시각 기준선과 디자이너 검수, E2E 테스트는 전체 페이지 흐름을 담당한다고 명시한다.

- [x] **2단계: 공식 참고 자료 확인**

Storybook 문서화와 인터랙션 테스트, Chromatic 시각 테스트와 UI 검수의 공식 문서 링크를 포함한다.

### 작업 2: 디자인 문서와 디자이너 QA 기록 추가

**파일:**

- 생성: `docs/design/README.md`
- 생성: `docs/design/qa/2026-07-16-designer-qa.md`

**입출력:**

- 입력: 프로젝트 논의에서 나온 디자이너 질문과 개발자 답변
- 출력: 반응형과 인터랙션 결정을 날짜별로 검토할 수 있는 기록

- [x] **1단계: 디자인 문서 목차 작성**

날짜별 QA, 인터랙션 명세, 피그마 참고 자료를 저장할 위치를 정의한다.

- [x] **2단계: 전체 QA 기록**

반응형 너비, 사자 눈동자와 영상 전환, 폭탄과 경고 스크롤 순서, 드래그 팀 갤러리, 재사용 가능한 Work·Profile 템플릿, 롤링페이퍼 접힘과 스크롤 동작을 기록한다. 확정된 결정과 구현 중 검증할 항목을 분리한다.

### 작업 3: 문서 연결 및 검증

**파일:**

- 수정: `AGENTS.md`
- 수정: `docs/conventions/README.md`
- 검증: 작업 1과 작업 2에서 생성한 모든 파일

**입출력:**

- 입력: ADR-0002와 디자인 문서 목차
- 출력: 향후 에이전트와 기여자가 찾을 수 있는 기준 문서

- [x] **1단계: 목차 링크 추가**

`AGENTS.md`에서 `docs/design/README.md`를 연결하고 컨벤션 목차에서 ADR-0002와 디자인 문서를 연결한다.

- [x] **2단계: 커밋하지 않고 검증**

파일 존재 여부, 상대 링크, 미완성 표시, 후행 공백, `AGENTS.md` 크기, staging 파일, Git 상태를 확인한다. 애플리케이션과 `package.json`이 없으므로 애플리케이션 테스트는 실행하지 않는다.
