- 요청:

- 결정:
  - 브라우저의 `maxLength`와 상태 갱신 양쪽에서 130자 제한을 적용한다.
  - 카운터는 `현재 글자 수 / 130` 형식으로 표시하고 입력 영역의 설명과 연결한다.
  - 작성 영역의 크기는 포커스 전후 동일하게 유지한다.
  - 입력창 본문은 모바일 `9~12px`, 태블릿 `12~14px`, 웹 `16~20px`의 기존 유동 크기로 복원한다.

  - 포스트잇의 고정 정사각형 크기와 `To`·`From` 위치는 유지하며, 남는 본문 공간을 더 사용한 뒤 긴 글만 말줄임 처리한다.
  - 기본값 `전체(모두)`는 regular, 실제 선택 수신자와 카드의 수신자 이름은 bold로 표시한다.
  - 수신자 이름과 하단 화살표는 동일한 flex 행에 두고, 필드 라벨에만 절대 위치를 적용한다.
  - 목업 데이터는 130자 이하의 메시지 8종을 서로 다른 줄바꿈으로 구성한다.
- 검증:
  - 400·600·1020·1350·1920px에서 130자를 입력해 카운터, 입력 제한, 본문 수용 여부를 확인했다.
  - 모든 규격에서 포커스 전후 작성 영역과 입력 글자 크기가 유지되고 카운터와 전송 버튼이 본문과 겹치지 않았다.
  - 하단 포스트잇은 130자 목업에서도 `From` 영역을 침범하지 않고 화면별 최대 줄 수에서 말줄임 처리되는지 확인했다.
  - 모든 규격에서 수신자 이름과 화살표의 계산된 위치가 `static`이며 선택 영역 안에서 수직 중앙 정렬되는 것을 확인했다.
  - 실제 수신자 선택 후 계산된 글꼴 굵기가 `700`으로 변경되는 것을 확인했다.

## QA-010 — Message 반복 줄바꿈에 의한 세로 넘침 방지

- 대상: `/message`, 메시지 작성 영역과 새로 생성되는 포스트잇
- 문제: 줄바꿈도 문자열 길이에는 1자로 계산되지만 화면에서는 새로운 한 줄의 높이를 차지하므로, 130자 제한만으로는 포스트잇의 세로 공간을 보호할 수 없다.
- 결정:
  - 메시지 본문은 기존과 동일하게 최대 130자로 제한한다.
  - 가장 좁은 모바일 포스트잇에서 한 줄이 차지하는 공간을 기준으로 줄바꿈 1회를 20자 사용량으로 계산한다.
  - 일반 문자는 1자, 줄바꿈은 20자를 사용한 것으로 합산해 총 사용량이 130을 넘지 않도록 입력을 정규화한다.
  - 남은 사용량이 한 줄보다 작을 때 추가한 줄바꿈은 공백으로 바꿔 뒤의 내용을 삭제하지 않고 같은 문단에서 이어지게 한다.
  - 서로 다른 운영체제의 줄바꿈 문자는 `\n`으로 통일한다.
  - 작성 영역 좌측 하단에는 별도의 줄바꿈 안내 없이 환산된 `현재 사용량 / 130`만 표시한다.
  - 카드의 화면별 글자 크기와 `line-clamp`는 예외적으로 긴 단어와 좁은 중간 화면을 막는 최종 안전장치로 유지한다.
- 검증:
  - 운영체제별 줄바꿈 정규화, 줄바꿈의 20자 환산, 최대 130 사용량 제한을 입력 규칙 테스트로 확인했다.
  - 400 × 880 화면에서 반복 줄바꿈을 입력했을 때 카운터에는 줄바꿈 문구 없이 환산된 사용량만 표시되는지 확인했다.
  - 동일한 메시지를 실제 포스트잇으로 추가해 본문 overflow, 본문과 `From` 겹침, `From`의 카드 이탈이 모두 발생하지 않는지 확인했다.

## QA-011 — Profile 상세 프로젝트 이미지 비율 통일

- 대상: `/profile/[id]`, Work 프로젝트 대표 이미지
- 재현: 1350px 이하에서는 이미지 컨테이너가 `1.8:1`이지만, 1350px보다 큰 화면에서는 높이가 `900px`로 고정되어 화면 폭에 따라 보이는 이미지 비율과 잘림 범위가 달라졌다.
- 결정:
  - 프로젝트 이미지 컨테이너에 전 반응형 구간 공통 `aspect-ratio: 1.8`을 적용한다.
  - 고정 높이를 제거하고 너비를 기준으로 높이가 계산되게 해 원본 3240 × 1800 이미지와 같은 비율을 유지한다.
  - 이미지는 기존 `object-fit: cover`를 유지해 이후 다른 원본이 연결되어도 컨테이너 비율과 레이아웃은 변하지 않게 한다.
- 검증:
  - `400, 600, 1020, 1350, 1351, 1500, 1920px`에서 컨테이너와 렌더링 이미지의 너비/높이 비율이 모두 `1.8`인지 브라우저에서 확인했다.
  - 1350→1351px 경계에서 컨테이너가 `1250 × 694.44px`에서 `1251 × 695px`로 연속적으로 변해 급격한 이미지 잘림 전환이 발생하지 않았다.
  - 1920px에서는 디자인 원본 기준인 약 `1620 × 900px` 크기를 유지했다.
