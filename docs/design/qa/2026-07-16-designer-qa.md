## 1. 화면 크기와 반응형

### 디자이너 질문

1920px, 1350px, 1020px, 600px, 400px의 다섯 너비를 고려하고 있다. 1920px 시안을 줄이면 레이아웃이나 텍스트가 넘칠 수 있지만, 1440px과 1280px 시안을 페이지마다 추가하면 디자인과 개발 분량이 지나치게 많아진다. 1920px을 기준으로 두고 고정 화면이 아닌 컨테이너 값을 조정하는 방향이 가능한가?

### 개발 답변

1920px을 PC 기준 디자인으로 사용해도 괜찮다. 실제 구현은 화면 전체를 1920px에 고정하지 않고 콘텐츠 컨테이너에 최대 너비, 중앙 정렬, 최소 좌우 여백을 적용한다.

- 1440px과 1280px의 전체 페이지 시안을 별도로 만들 필요는 없다.
- 1920px과 모바일 시안을 중심으로 제작한다.
- 1350px, 1020px, 600px에서는 카드 열 수, 메뉴, 정렬처럼 레이아웃이 변하는 규칙만 표시한다.
- 텍스트 줄바꿈, 긴 제목, 최소 여백이 깨지는 대표 화면만 중간 너비로 확인한다.
- 배경은 화면 전체로 확장하고 주요 콘텐츠는 최대 너비 안에서 배치한다.

### 구현 검증

- 주요 화면을 1920px, 1350px, 1020px, 600px, 400px에서 확인한다.
- 콘텐츠 최대 너비와 좌우 여백의 정확한 값은 실제 시안을 적용한 뒤 피그마와 비교해 확정한다.
- 레이아웃 전환이 없는 컴포넌트에는 모든 viewport Story를 만들지 않는다.

## 2. 메인: 눈동자 추적과 사자 등장

### 디자이너 질문

사자의 눈동자가 커서를 따라간 뒤 사자가 벽을 뚫고 등장하는 영상을 자연스럽게 연결할 수 있는가?

### 개발 답변

가능하다. 눈동자는 분리된 이미지 레이어로 커서를 따라가게 하고, 사자가 벽을 뚫는 복잡한 움직임만 짧은 영상으로 연결한다.

자연스러운 전환을 위해 다음 자료가 필요하다.

- 인터랙션 시작 정지 이미지
- 분리된 눈동자 이미지
- 사자가 등장하는 짧은 영상
- 영상의 마지막 프레임 이미지
- 같은 캔버스 비율, 위치, 색상을 사용하는 시작 이미지와 영상 첫 프레임

눈동자가 중앙으로 돌아온 뒤 벽이 흔들리는 순간 영상을 시작하면 이미지와 영상 교체를 자연스럽게 가릴 수 있다. 모바일에는 커서가 없으므로 기본 눈 움직임과 탭 또는 스크롤 트리거를 제공한다.

### Storybook 상태

- `Initial`
- `EyeTracking`
- `EyesCentered`
- `WallBreaking`
- `FinalPose`

연속적인 커서 이동과 영상 전체 재생은 실제 페이지에서 추가로 검수한다.

## 3. 메인: 폭탄, 경고창, 콘셉트 소개

### 디자이너 질문

스크롤했을 때 폭탄과 경고 메시지가 나온 뒤 경고창이 사라지고 콘셉트 설명이 나타나는 시점을 어떻게 구성하는가?

### 개발 답변

하나의 스크롤 섹션을 다음 세 상태로 나눈다.

1. 폭탄 등장
2. 경고 메시지 표시
3. 경고창이 사라지며 콘셉트 설명 등장

초기 기준으로 섹션 진행도 `0~35%`, `35~65%`, `65~100%`를 각 상태에 배정할 수 있다. 이 수치는 고정 요구사항이 아니라 프로토타입의 체감 속도를 확인하기 위한 시작값이다.

디자인에서는 `BombEntering`, `WarningVisible`, `ConceptVisible`의 대표 화면을 전달한다. 전환 구간은 개발 프로토타입을 함께 보면서 조정한다.

## 4. About: 졸업전시 팀 사진

### 디자이너 질문

사용자가 팀 사진을 마우스로 잡고 좌우로 넘기는 인터랙션을 구현할 수 있는가?

### 개발 답변

가능하다.

- PC 마우스: 클릭 후 드래그
- 트랙패드: 좌우 스크롤
- 모바일: 터치 스와이프
- 키보드 및 보조 입력: 이전·다음 버튼

사진 크기, 간격, 시작 위치, 마지막 위치를 디자인에 표시한다. 기본 동작은 끝에서 멈추는 방식으로 하고, 무한 반복은 디자인상 필요성이 확인될 때 추가한다.

### Storybook 상태

- `Start`
- `Dragging`
- `End`

## 5. Work 및 Profile

### 디자이너 질문

레이아웃이 통일된다면 하나의 와이어프레임과 작품·작가별 사진 및 내용을 전달해도 되는가?

### 개발 답변

가능하다. 각 작품과 작가마다 별도 시안을 만들 필요는 없다. 다음 템플릿을 각각 하나씩 제공한다.

- 작품 목록
- 작품 상세
- 작가 목록
- 작가 상세

데이터는 공통 양식으로 전달하고, 다음 예외 상태만 별도 시안이나 메모로 제공한다.

- 긴 제목과 긴 설명
- 이미지 여러 장
- 이미지 또는 소개 없음
- 팀 프로젝트

### Storybook 상태 예시

- `Default`
- `LongTitle`
- `MissingImage`
- `TeamProject`
- `MultipleWorks`

## 6. Message: 편지 형태와 접힘

### 디자이너 질문

편지를 작성한 뒤 포스트 형태가 변형되고 접히는 인터랙션을 고려하고 있다. Auto Layout 적용 시 형태가 변형되는 문제와 `TO.` 작가 이름 표시, 스크롤 시 편지 배치를 어떻게 처리하는가?

### 개발 답변

편지 접힘은 구현 가능하다. 하나의 Auto Layout 프레임을 억지로 변형하기보다 다음 상태를 각각 디자인한다.

1. 편지 작성 중
2. 작성 완료
3. 접히는 중
4. 접힌 편지가 게시판에 배치된 상태

각 상태는 동일한 캔버스와 기준점을 사용한다. 필요한 경우 편지 앞면, 뒷면, 접힌 상태를 분리된 레이어나 이미지로 전달한다.

사용자가 편지 작성 전에 선택한 작가 이름을 데이터와 연결해 `TO. 작가 이름` 형태로 표시한다.

편지를 완전히 랜덤한 절대 위치에 배치하면 반응형과 읽기 순서가 불안정하므로, 기본 그리드 안에서 여러 시각 변형이 섞이는 방식을 사용한다.

- PC: 3~4열
- 태블릿: 2~3열
- 모바일: 1~2열
- 최신 편지를 먼저 표시
- 스크롤 진입 시 순차적으로 등장
- 데이터가 많아지면 더보기 또는 추가 로딩 적용

디자인에서는 기본 편지 형태 3~5개와 PC·모바일 배치 예시를 제공한다.

### Storybook 상태

- `Writing`
- `Submitted`
- `Folding`
- `Folded`
- `EmptyBoard`
- `LongContent`
- `MobileBoard`

실제 DB 저장, 추가 로딩, 관리자 숨김은 통합 테스트와 E2E 테스트에서 확인한다.
