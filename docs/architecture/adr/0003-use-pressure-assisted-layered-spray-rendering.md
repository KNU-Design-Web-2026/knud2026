# ADR-0003: 메인 스프레이에 압력 보조형 레이어드 래스터 렌더링을 사용한다

- 상태: 제안됨
- 결정일: 2026-08-28
- 적용 범위: 메인 Hero의 클릭·드래그 스프레이 인터랙션

## 배경

메인 Hero의 스프레이는 전시 그래픽의 물성과 에너지를 보강하는 직접 조작 요소다. 현재 구현은 Canvas 2D에서 중심 타원 하나와 균일한 입자를 반복해 그린다. 이 구조는 동작 자체는 명확하지만, 참고 이미지에서 보이는 다음 특징을 충분히 표현하지 못한다.

- 중심부가 진하고 두꺼우며, 같은 획 안에서도 도포량이 달라진다.
- 가장자리에는 작은 미세 입자가 집중도에 따라 불규칙하게 퍼진다.
- 길게 누르거나 천천히 이동한 구간은 더 조밀하게 보인다.
- 액체가 고이는 일부 지점에만 짧은 드립이 생기며, 모든 획이 꼬리처럼 늘어나지 않는다.

또한 `PointerEvent.pressure`는 펜 입력에서는 실제 압력 값을 제공할 수 있지만, 일반 마우스에서는 대개 고정값 또는 0에 가까운 값을 제공한다. 마우스 사용자가 대부분인 공개 전시 사이트에서 pressure 하나만으로 도포량을 결정하면 기기마다 결과가 달라진다.

## 결정

메인 스프레이를 **Canvas 2D 기반의 압력 보조형 레이어드 스탬프**로 렌더링한다. 새로운 WebGL 의존성이나 이미지 텍스처는 추가하지 않는다.

### 입력 해석

- 펜 입력에서 유효한 `event.pressure`가 연속적으로 제공되면 이를 도포 강도의 우선 신호로 사용한다.
- 마우스와 pressure 미지원 입력에서는 실제 클릭 강도를 추정하지 않는다. 대신 **누른 시간, 이동 속도, 같은 위치에 머문 정도**로 도포 밀도를 보정한다.
- 빠른 이동은 경로 사이의 빈틈이 생기지 않도록 보간하되, 스탬프 개수를 무제한으로 늘리지 않고 프레임마다 마지막 입력점만 소비한다.
- 색상은 현재처럼 스트로크 시작마다 순환하고, 하나의 스트로크 안에서는 색을 고정한다.

### 시각 레이어

각 스탬프는 난수를 생성한 뒤 재사용하는 세 레이어로 구성한다.

| 레이어 | 역할 | 렌더링 기준 |
| --- | --- | --- |
| 중심 도포층 | 두께·채도·불투명도의 핵심 | 압력/밀도에 따라 반지름과 알파를 키운 2~3개의 겹친 타원 |
| 가장자리 안개층 | 분사된 페인트의 부드러운 경계 | 중심보다 낮은 알파와 작은 반지름의 근접 입자 |
| 외곽 비산층 | 참고 이미지의 불규칙한 튐 | 적은 수의 미세 점·희소한 큰 점을 방향과 수직 방향으로 분산 |

- 중심 도포층은 현재보다 높은 불투명도로 시작해 색의 채도를 유지한다. `shadowBlur`, 전체 캔버스 블러, 매 프레임 난수 생성은 사용하지 않는다.
- 드립은 정지 또는 저속 구간에서 낮은 확률로만 생성한다. 드립 수와 길이에 상한을 두어 모든 선이 물줄기처럼 보이는 현상을 피한다.
- 각 스탬프의 입자 위치·크기·알파는 생성 시 한 번 확정한다. 프레임마다 모양이 바뀌지 않아 깜빡임이 없다.

### 성능 경계

- 포인터 이벤트는 최신 위치와 입력 속성만 저장하고, 도포·보간·렌더링은 하나의 `requestAnimationFrame` 루프에서 실행한다.
- 캔버스 DPR은 2로 제한하고, 스프레이 중이거나 사라지는 스탬프가 남았을 때만 프레임을 예약한다.
- 스탬프별 데이터는 객체 풀 또는 재사용 가능한 배열로 관리한다. 수명이 끝난 스탬프는 즉시 재사용 후보로 돌린다.
- 스탬프의 시각 수명은 현재처럼 1.8초 유지 후 0.6초 페이드아웃을 기본값으로 한다. 최대 동시 스탬프 수는 사라지는 효과를 훼손하지 않는 범위에서 별도 성능 측정 후 확정한다.
- `prefers-reduced-motion`과 정밀 포인터 미지원 환경에서는 스프레이를 비활성화한다.

## 선정 이유

### 1. 참고 이미지의 물성을 적은 연산으로 분해할 수 있다

실제 스프레이 질감은 중심의 젖은 도포와 주변의 건조한 비산 입자가 함께 있을 때 자연스럽다. 이를 큰 이미지 스프라이트 하나로 반복하면 회전·크기 변화가 단조롭고, 이미지를 매번 합성하면 메모리와 전송 비용도 커진다. 원형·타원·작은 점만으로 레이어를 분리하면 색을 즉시 바꾸고 입력 강도에 따라 밀도를 조절할 수 있다.

### 2. 마우스와 펜 모두에서 예측 가능한 결과를 제공한다

펜은 pressure를 활용해 실제 힘의 차이를 반영할 수 있다. 반면 마우스는 pressure를 신뢰하지 않고 시간·속도 기반 보정으로 처리하면, 일반 사용자가 클릭을 유지했을 때도 충분히 두꺼운 스프레이를 만들 수 있다. 지원하지 않는 하드웨어에서 가짜 필압을 약속하지 않는 것이 핵심이다.

### 3. 성능 병목을 입력과 렌더링에서 분리할 수 있다

포인터 이동은 디스플레이 주사율보다 자주 발생할 수 있다. 이벤트마다 모든 입자를 생성·그리면 CPU 작업과 Canvas 호출이 누적된다. 최신 입력을 한 프레임에 한 번 소비하면, 화면 갱신 주기에 맞춰 보간하므로 빠른 드래그의 연결성은 유지하면서 과도한 호출을 줄일 수 있다.

## 검토한 대안

### 캔버스에서 매 포인터 이벤트마다 입자를 즉시 생성한다

구현은 단순하지만 고주사율 마우스와 긴 드래그에서 이벤트 수만큼 객체와 draw call이 증가한다. 현재 느껴지는 버벅임의 원인이 될 수 있으므로 선택하지 않는다.

### pressure 값만으로 도포량을 제어한다

펜에서는 효과적이지만 마우스에서는 고정값 또는 0으로 동작할 수 있다. 공개 사이트의 주 입력 환경을 안정적으로 지원하지 못하므로 단독 기준으로 선택하지 않는다.

### 비트맵 스프레이 브러시 이미지를 반복 합성한다

사진 같은 질감을 즉시 얻을 수 있으나, 크기·회전·색상 변형에서 반복감이 두드러지고 자산 관리가 늘어난다. 필요한 질감이 Canvas 원형·타원·입자 조합을 넘어설 때만 재검토한다.

### WebGL 파티클 시스템을 도입한다

대량의 입자와 긴 잔상을 처리하기에는 유리하지만, 현재 Hero 한 영역의 짧은 수명 효과에는 초기화·디버깅·접근성 대응 비용이 크다. Canvas 2D 측정 결과가 목표 프레임을 충족하지 못할 때만 검토한다.

## 구현 및 검증 계획

1. 스탬프 데이터에 `intensity`, `core`, `mist`, `overspray`, `drip` 레이어 속성을 추가한다.
2. `pointermove`는 최신 입력을 저장하고, animation frame에서 거리 보간과 스탬프 생성을 수행하도록 바꾼다.
3. 펜·마우스 각각에서 짧은 클릭, 긴 클릭, 느린 드래그, 빠른 드래그를 녹화해 중심 두께와 비산 입자 분포를 확인한다.
4. Chrome Performance 패널에서 10초 연속 드래그를 측정한다. scripting, rendering, long task, canvas 호출 수, 메모리 증가량을 변경 전후로 기록한다.
5. 1920px와 1350px 뷰포트에서 시각 검수하고, reduced motion·터치 환경에서 비활성 상태를 확인한다.

## 수용 기준

- 약하게 누르거나 빠르게 움직인 획보다, 펜의 높은 압력 또는 오래 머문 획의 중심부가 더 두껍고 진하게 보인다.
- 색상은 중심부에서도 탁해지지 않고, 주변 입자는 중심부보다 옅고 희소하다.
- 드립은 일부 정지 지점에서만 짧게 나타나며 경로 전체가 꼬리처럼 이어지지 않는다.
- 10초 연속 드래그 후에도 수명이 끝난 스탬프가 메모리에 누적되지 않는다.
- reduced motion 및 정밀 포인터 미지원 환경에는 인터랙션이 나타나지 않는다.
