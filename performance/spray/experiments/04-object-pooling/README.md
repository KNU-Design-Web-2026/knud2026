# 실험 04 — 스탬프 객체 풀링

## 가설

만료된 스탬프와 82개 입자 객체를 다음 입력에서 다시 사용하면 빠른 드래그 중 GC 압력을 줄일 수 있다고 예상했다. 화면 결과는 같은 seed에서 동일한 수치 데이터를 다시 쓰므로 바뀌지 않는다.

## 결과

기존 배포 기준의 `fast-drag` 중앙값과 로컬 프로덕션 빌드 3회 중앙값을 비교했다.

| 조건 | Render p95 | Frame interval p95 | Peak active stamps |
| --- | ---: | ---: | ---: |
| 기존 Native | 7.6ms | 20.3ms | 733 |
| 객체 풀 Native | 8.1ms | 19.6ms | 733 |
| 기존 CPU 4× | 27.2ms | 38.0ms | 685 |
| 객체 풀 CPU 4× | 29.9ms | 39.5ms | 689 |

`CanvasRenderingContext2D.fillStyle`을 읽고 비교하는 부가 실험은 CPU 4×에서 30.3ms까지 악화되어 즉시 제거했다. 속성 getter 비용을 피하고 단순 대입으로 되돌린 뒤에도 객체 풀의 유의미한 개선은 관찰되지 않았다.

## 판정

기각한다. 객체 할당보다 프레임마다 반복되는 원 경로 생성과 fill 호출이 더 큰 병목이며, 만료 스탬프를 풀로 반환하는 작업이 render 구간에도 추가된다. 원시 JSON과 대표 trace는 하위 디렉터리에 보존한다.
